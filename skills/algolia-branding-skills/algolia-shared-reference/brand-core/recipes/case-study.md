# recipe: case-study — Algolia customer case study

output: structured challenge-solution-results story (sales leave-behind + web publication)
mode: create or rebrand

## inputs
customer name + industry · customer contact (name, title) for attribution · the pre-Algolia challenge ·
Algolia products/features used · quantified results · direct customer quotes (if any) · technical details (optional) · timeline to go-live

## structure (in order)
1. customer overview — one paragraph (3–4 sentences): company, industry, size, what they do, why search matters; logo placement guidance
2. the challenge (H2) — 2–3 paragraphs; lead with business impact (lost revenue, poor UX, dev friction), then technical limits; use the customer's words where possible
3. the solution (H2) — 2–3 paragraphs; name the specific Algolia products (from product-names.md); describe the approach without excess jargon
4. technical sidebar (optional) — boxed; products used, integration method, data volume, index config, custom features; bullets; background = light-gray (`--bg-light-gray`)
5. the results (H2) — lead with the hero metric; then 2–4 supporting metrics; each = large number in primary color with a descriptive label; give context (before/after, timeframe)
6. pull quotes — 2–3; large text in primary color + attribution (name, title, company); Sora has no italic — use weight/size, never a faux-italic transform; one in challenge, one in results
7. key-metrics callout strip — 3–4 quantified results; large numbers in primary color, labels in body color
8. CTA — "Ready to see similar results?" + button (demo/trial) + secondary link to related case studies
9. metadata — industry tag, company size, products used, region, use-case type

## format-specific checks
every metric sourced/attributed · product names current · no italics · logo not redrawn

## then
engine runs algolia-brand-check on the complete case study; fix to ≥8.
